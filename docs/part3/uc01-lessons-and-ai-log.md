### 2. Hardest Technical Problems and How I Solved Them
1. **Classic ASP.NET MVC 5 Razor C# 5 Compilation Error:** When launching the app on IIS Express, `_Layout.cshtml` threw a runtime compile error (`CS1525`) on the C# 6 null-conditional operator (`?.`). Without Roslyn CodeDom installed, IIS Express compiles Razor views with the C# 5 compiler (`v4.0.30319\csc.exe`). I replaced `?.` and `$""` in all `.cshtml` files with standard C# 5 null checks and `string.Format`, and added a pre-commit scan across all Razor views so the bug never recurred.
2. **EF6 Migration Scaffolding & Foreign-Key Delete Order:** Generating the `InitialCreate` EF6 migration programmatically initially omitted the embedded `.resx` `Target` model snapshot, which prevented `MigrateDatabaseToLatestVersion` from running cleanly. Writing the `.resx` resource via `ResXResourceWriter` and registering it as `<EmbeddedResource>` fixed database auto-migration. Additionally, because we disabled cascade delete (`WillCascadeOnDelete(false)`) to protect order history, test cleanup helpers had to explicitly remove `OrderStatusHistories`, `PaymentRecords`, and `OrderLines` before removing `Orders`.
3. **Catching a Subtle BR8 Bug During QA Review:** While writing the formal QA test suite against the specification, I noticed `OrderService.CalculateHubLoad` initially counted `Placed` and `Ready` orders alongside `Confirmed` and `Preparing`. Re-reading BR8 and `architecture.md` confirmed only `Confirmed` and `Preparing` count toward kitchen load. Fixing the query (`74081c9`) and writing dedicated integration tests (`CalculateHubLoad_CountsOnlyConfirmedAndPreparingOrders_MatchesBR8` and `Quote_WhenHubLoadReaches90Percent_ThrowsBR8AndSuggestsAlternativeHubs`) prevented a serious requirement mismatch during live demo.
